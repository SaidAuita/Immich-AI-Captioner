# ImmichCaptioner — Project Status & Architecture

**Последнее обновление:** 2026-09-25  
**Статус проекта:** Полностью рабочий (Production Ready)  
**Компоненты:**
- Windows GUI клиент (`ImmichCaptioner.exe` / `ui_app.py`)
- Windows CLI воркер (`main.py`)
- Linux Metadata ExifTool демон (`apply_metadata.py`, `immich-metadata-worker.service`)

---

## 1. Архитектура и принцип работы

Система решает две главные задачи:
1. **Качественное нейросетевое тегирование в Immich без размытия поиска** (модель Qwen3-VL в LM Studio на RTX 3080 Ti).
2. **Вечное сохранение метаданных в исходных файлах (Source of Truth)**: вшивание стандартизированных IPTC/XMP метаданных прямо в оригинальные файлы на сервере `cladovka`. Если база данных Immich будет повреждена или переустановлена, все теги, заголовки и описания останутся внутри самих файлов и подтянутся при повторном сканировании.

```
[ Рабочий ПК (или Домашний ПК) ]
     │
     ├─► 1. Скачивает превью фото через Immich REST API (KeenDNS / LAN)
     ├─► 2. Qwen3-VL в LM Studio анализирует изображение
     ├─► 3. Возвращает строгий JSON: { title, tags, description, ocr }
     ├─► 4. Обновляет Immich:
     │      - Привязывает теги через /api/tags
     │      - В description Immich пишет чистые теги через запятую (tags_only)
     │
     └─► 5. Записывает задание <asset_id>.json в очередь DropSync
                               │
                       [DropSync канал]
                               │
                               ▼
               [ Домашний сервер cladovka ]
                               │
                               ▼
   6. Демон apply_metadata.py (systemd-сервис):
      - Читает задание из queue/<asset_id>.json
      - Находит файл в /mnt/photos/immich/upload/...
      - Вшивает метаданные через exiftool:
          • JPG/PNG/WebP/TIFF: прямо в тело файла
          • RAW/Видео: в сопутствующий .xmp sidecar
      - Обновляет файл статистики stats.json
      - Перемещает задание в done/
```

## 2. Стандарты метаданных (IPTC / XMP / EXIF)

При записи в оригинальные файлы используются отраслевые стандарты (полная совместимость с Adobe Photoshop, Bridge, Lightroom, DigiKam, ACDSee, PhotoPrism, Windows Explorer):

| Сущность | Поля в файле / XMP | Назначение |
| :--- | :--- | :--- |
| **Теги (Keywords)** | `XMP-dc:Subject`<br>`IPTC:Keywords`<br>`EXIF:XPKeywords`<br>`XMP-lr:hierarchicalSubject` | Поиск по ключевым словам в любых просмотрщиках и Проводнике Windows |
| **Заголовок (Title)** | `XMP-dc:Title`<br>`XMP-photoshop:Headline`<br>`IPTC:Headline`<br>`IPTC:ObjectName`<br>`EXIF:XPTitle` | Краткая суть кадра (3–5 слов) |
| **Описание (Caption)** | `XMP-dc:Description`<br>`IPTC:Caption-Abstract`<br>`EXIF:ImageDescription` | Описание сцены |
| **Кодировка и передача** | `UTF-8 Argfile Pattern`<br>`-codedcharacterset=utf8`<br>`-charset iptc=utf8` | 100% чистая кириллица без `??????` на Windows и Linux (передача аргументов через временный UTF-8 файл) |
| **Пути на диске** | `/mnt/photos/immich/upload/...`<br>`/mnt/photos/immich/library/...` | Поддержка как загруженных через мобильные клиенты фото, так и структурированной библиотеки Immich |
| **Защита очереди** | `.keep` файл в `queue/` | Защита от случайного удаления папки очереди синхронизатором DropSync |

## 3. Режимы описания в Immich (`immich_description_mode`)

В `config.json` и в выпадающем меню GUI доступно 3 режима:
1. **`tags_only` (по умолчанию, Рекомендуется)**:
   - В поле описания Immich записываются строго ключевые слова через запятую (`яблоко, гниль, повреждение, белая поверхность`).
   - Исключает словесный шум ("на фотографии", "запечатлен", предлоги и глаголы).
   - Обеспечивает 100% точность полнотекстового поиска Immich без ложных срабатываний.
2. **`title_and_tags`**:
   - Заголовок на первой строке + строка `Теги: ...`.
3. **`full`**:
   - Полное связное описание + теги + распознанный текст (OCR).

## 4. Параллельная работа нескольких клиентов (Работа ⇄ Дом)

Вы можете запускать `ImmichCaptioner.exe` (или `main.py`) **одновременно на нескольких компьютерах** (например, рабочий ПК и домашний ПК):
1. **Отсутствие конфликтов задач в Immich**:
   - Клиент запрашивает у Immich фото без описания (`get_unprocessed_assets`).
   - Как только один клиент обновляет фото, у него появляется описание в базе Immich.
   - Второй клиент при следующем опросе автоматически получает другие, еще не обработанные фотографии.
2. **Уникальность файлов в очереди DropSync**:
   - Имена файлов заданий строго уникальны: `<asset_id>.json` (UUID ассета в Immich). Воркеры не перезаписывают чужие задания.
3. **Сетевое окружение**:
   - Immich доступен по локальному IP `http://immich-server:2283` (или через обратный прокси / VPN).
   - Путь к очереди метаданных: папка очереди DropSync / SMB шара `\\NAS\Exchange\_CODE\ImmichMetadata\queue`.

## 5. Расположение файлов и путей

### Сервер (Linux):
- Папка заданий и сервиса: `/opt/immich-metadata/`
  - `apply_metadata.py` — фоновый скрипт
  - `immich-metadata-worker.service` — systemd юнит
  - `install_service.sh` — скрипт установки сервиса
  - `queue/` — входящие задания от клиентов
  - `done/` — завершенные задания
  - `commands/` — команды удаленного управления (`restart.cmd`)
  - `stats.json` — живая статистика работы
- Оригиналы фото Immich на диске: `/mnt/photos/immich/upload/` (соответствует `/data/` внутри docker-контейнера).

### Клиентский ПК (Windows):
- Проект: `C:\_CODE\Utilites\ImmichCaptioner\`
  - `ImmichAI_Captioner_Standalone.exe` / `ImmichAI_Captioner_Worker.exe` — собранные приложения
  - `ui_app.py` — исходный код GUI
  - `captioner.py` — модуль работы с VLM
  - `immich_client.py` — клиент Immich API
  - `config.json` — конфигурация
- Сетевая папка обмена: `\\NAS\Exchange\_CODE\ImmichMetadata\`

## 6. Управление сервисом на сервере

Установка сервиса в 1 команду:
```bash
cd /opt/immich-metadata
sudo bash install_service.sh
```

Команды управления:
- Статус: `sudo systemctl status immich-metadata-worker`
- Перезапуск вручную: `sudo systemctl restart immich-metadata-worker`
- Просмотр лога в реальном времени: `sudo journalctl -u immich-metadata-worker -f`
- Удаленный перезапуск из GUI: кнопка `[ 🔄 Воркер сервера ]` в окне `ImmichCaptioner.exe`.
- Самообновление: при обновлении файла `apply_metadata.py` через DropSync сервис перезапускается автоматически.

## 7. Функции тестирования в GUI

1. **Тест одного фото по URL/ID**:
   - Вставьте ссылку на фото из адресной строки браузера Immich в поле `🧪 Тест фото` и нажмите `⚡ Распознать`.
   - Фото мгновенно распознается, превью и теги отобразятся в окне, метаданные обновятся в Immich и отправятся на сервер.
2. **Тест 5 фото**:
   - Кнопка `🧪 Тест 5 фото` обрабатывает ровно 5 фото из очереди и автоматически встает на паузу.
3. **Безопасная переделка всего архива**:
   - Кнопка `[ ⚠️ Переделать всё ]` открывает модальный диалог подтверждения.
   - При подтверждении сбрасывает локальный кэш `state.json`, устанавливает счётчики в `0 / 18 292`, переводит воркер на 1-ю страницу и включает режим `force_all=True`, перезаписывая старые описания новыми качественными тегами для всей библиотеки Immich.
   - Корректно синхронизирует статистику через эндпоинт `/api/server/statistics`.
   - Порог троттлинга GPU оптимизирован до 85% для избежания ложных срабатываний на RTX 3090.
4. **Переключатель режима нагрузки (`Auto 85% / ON`)**:
   - `Auto 85%`: мониторит нагрузку видеокарты и ставит процесс на мягкую паузу при GPU > 85% или активности ресурсоемких процессов.
   - `ON`: полностью отключает контроль троттлинга. Распознавание работает непрерывно на максимальной скорости независимо от фоновой нагрузки GPU.
   - Выбор запоминается в `config.json` между перезапусками.
5. **Исправление сохранения тегов**:
   - Устранена ошибка обращения к `self.engine.config` при формировании описания Immich и очереди DropSync, из-за которой фото после VLM помечалось ошибкой. Полный цикл (скачивание -> VLM -> Immich -> DropSync -> state) протестирован и работает корректно.

## 9. Мультиязычность (8 языков) и раздельный выбор языков описания и тегов (v1.1.0)

- **Полная локализация интерфейса (8 языков)**:
  - Реализованы локали: `en` (English), `ru` (Русский), `de` (Deutsch), `es` (Español), `fr` (Français), `ja` (日本語), `pt` (Português), `zh` (简体中文).
  - Выпадающее меню выбора языка интерфейса `[ 🌐 UI ▾ ]` в шапке окна с мгновенным переключением всех надписей и сохранением в `config.json` (`ui_language`).
- **Раздельный выбор языков генерации AI**:
  - **Язык описания (`caption_language`)**: формирует заголовок и лаконичное описание сцены для Immich на выбранном языке (например, русский).
  - **Язык тегов (`tags_language`)**: формирует поисковые теги / ключевые слова для Immich и вшивания ExifTool в файлы (`IPTC:Keywords`, `XMP-dc:Subject`) на выбранном языке (например, английский).
  - Это решает классическую проблему совместимости: пользователи часто хотят читать описания на родном языке, но сохранять теги в файлах на английском для идеальной совместимости с Adobe Lightroom, Capture One, стоками и международными поисковиками.
- **Динамический VLM-промптинг (`captioner.py`)**:
  - Метод `get_system_prompt(desc_lang, tags_lang)` инструктирует модель зрения (Qwen2.5-VL / Qwen3-VL) строго разделять языки генерации.
- **Интерфейс настроек генерации**:
  - Выделенная панель `[ Описание: ... ] [ Теги: ... ] [ В Immich писать: ... ]`.
  - Синхронизация с воркером и сохранение в `config.json` / `worker_config.json`.
